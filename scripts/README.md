# 公告归档

在项目根目录执行，使用项目现有 Node.js 和 pnpm 环境。

```sh
# 只预览，不移动文件
pnpm notices:organize

# 确认预览后实际整理
pnpm notices:organize --apply

# 指定参考日期进行预览
pnpm notices:organize --today 2026-11-11

# 运行临时目录内的文件操作测试
pnpm notices:test
```

脚本扫描 `docs/notices` 及其子目录，按日期重新归类：

| 日期范围 | 位置 |
| --- | --- |
| 当天及未来日期 | `docs/notices/` 根目录 |
| 本周已经过去的日期 | `docs/notices/本周/` |
| 本月内、更早的日期 | `docs/notices/本月/` |
| 本年内、更早的日期 | `docs/notices/本年/` |
| 以前年度 | `docs/notices/2025/` 等实际年份目录 |

参考日期使用北京时间，周一为每周第一天。上一年度的公告始终进入年份目录，即使它在跨年的同一周内。

优先使用 frontmatter 的 `date`。仅当日期字段缺省时，才使用文件名开头的 `YYYY-MM-DD`。无效或缺失日期保持原位置并提示。同名冲突时停止，不覆盖文件。

仅移动 `.md` 公告，保留原文件名和内容字节，跳过所有 `index.md`、数据加载器、资源及符号链接，不删除空文件夹。每次运行都重新检查已归档公告，因此本周内容会随时间转入本月、本年或年份目录。

**移动目录会改变详情页 URL。**网站公告索引和自动侧栏会在下次构建时使用新路径，原有外部链接不会自动重定向。先查看预览，再决定是否执行。

Pages CMS 的公告集合覆盖 `docs/notices` 并允许子文件夹，新公告放在根目录。

## GitHub 每日自动归档

`.github/workflows/organize-notices.yml` 每天北京时间 **00:10** 调用归档脚本。GitHub 的定时任务可能排队延迟；本地电脑无需开机。没有配置 `push` 触发，CMS 发布后不会立即归档。

工作流会先运行测试，整理公告，再构建和检查站点；全部通过后，仅提交 `docs/notices` 内的路径变化。没有变化时不提交。使用 GitHub Actions 自带令牌及机器人身份，不需要个人 SSH 密钥或本地路径。

如果运行期间 CMS 又产生新提交，普通推送会拒绝，本次任务会失败并保留日志；不会强推或覆盖 CMS 更新。可在下一次定时任务中继续处理。

本地只把 GitHub 公告拉取下来。本地运行上面的 `--apply` 仅用于人工诊断；日常归档交给 GitHub 工作流，避免产生两套不同目录。
